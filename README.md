# SWRMC — Decor Editor

Редактор декораций для Minecraft: загрузка Blockbench/Vanilla JSON и OBJ-моделей, предпросмотр, настройка OBB-коллизий и экспорт папки с моделью и промежуточным описанием коллизий.

## Возможности

- точные, кластерные и упрощённые OBB-коллизии;
- выбор и перемещение боксов, ручная правка и `Ctrl/Cmd+Z`;
- одиночные и мультитекстурные модели с atlas;
- импорт моделей с `parent` из resource pack;
- безопасный экспорт `model.json`, `collision.json`, `meta.json` и PNG.

## Запуск

```bash
cargo run --release
```

Перетащите JSON- или OBJ-модель и связанные PNG в окно редактора, настройте коллизии и выберите папку для экспорта.

## Релиз

В GitHub Actions запустите workflow **Build SWRMC** вручную и укажите тег версии. Сборки Windows, macOS Apple Silicon и Linux появятся в созданном релизе.

## Свет декора

После импорта модели откройте вкладку **Свет** в правой панели.
Отметьте исходные боксы и нажмите **Сделать выделенные источниками** либо
добавьте **Отдельный LED** с положением в пикселях модели (16 = 1 блок).
Фильтр **Только источники** скрывает боксы без света.

- Основное: включение, тип, палитра / HEX, интенсивность, радиус, размер и затухание.
- Конус: направление численно или стрелкой в сцене, внутренний и внешний
  **полууглы**. Настройки сохраняются при переключении на точку.
- Атмосфера: объёмное рассеяние, пять режимов мерцания, глубина, частота, duty и seed.
- Четыре пресета записывают конкретные параметры; ID остаётся прежним.
- День/ночь, пол и стена, пауза и десятисекундное проигрывание помогают оценить свет.
  Радиус и размеры заданы в блоках при масштабе декора 1.
- Изменения света отменяются через **Ctrl/Cmd+Z**. Экспорт и отмена доступны над
  прокручиваемым инспектором.

Экспорт сохраняет `light` в исходном элементе или `lights` в корне `model.json`,
не дублируя источник. ID постоянны, новые источники получают свободный ID;
импорт и экспорт проверяют уникальность, диапазоны, цвет, направление и углы.
Поля геометрии и неизвестные дополнительные поля сохраняются. Число источников
не ограничено бюджетом игрового рендера.

Предпросмотр приблизительный: цветное освещение поверхности без теней,
с ориентировочным мерцанием; он не воспроизводит шейдер LightFX и объёмное
рассеяние. Для окончательной проверки используйте игру. Для гирлянд лучше
группировать близкие LED в несколько источников. Размер источника не делает
его физически точным area-light. Новый `collision.json` использует промежуточный контракт `collision_asset` v1.
Старые файлы OBB v2 и min/max по-прежнему импортируются. Версия v3 из игрового
контракта размещённого декора не относится к этому формату.

Проверки: `cargo test --offline` (включая контракт света, сохранение полей,
преобразования бокса, мерцание и 300 источников).

## OBJ и промежуточные коллизии

Загрузка через кнопку «Загрузить модель» или drag-and-drop поддерживает `.obj`.
Импортируются индексированные вершины, UV и faces (`v`, `v/vt`, `v//vn`,
`v/vt/vn`); поддерживаются отрицательные индексы, quads и вогнутые polygons.
Группы, smoothing и материалы MTL при импорте игнорируются. Нормали поверхности
для предпросмотра вычисляются из треугольников. Можно загрузить одну PNG-текстуру
по UV модели; соседний PNG с именем OBJ загружается автоматически. Это не
полноценный multi-material OBJ renderer.

По умолчанию OBJ: правая система координат, Y вверх, 1 единица = 1 блок,
origin `(0,0,0)`. Для OBJ в пикселях Minecraft задайте масштаб `0.0625`.
Настройки задают `local = (source - origin) * scale`; опция отражения Z меняет
handedness и порядок вершин при экспорте. Transform перемещает и масштабирует
уже созданные primitives вместе с моделью и отменяется через Ctrl/Cmd+Z.
JSON сохраняет прежние координаты: `((x-8)/16, y/16, (z-8)/16)`.

Автогенерация OBJ создаёт общий AABB. Детальная коллизия настраивается вручную:
добавьте AABB, OBB или Capsule, задайте center, размеры, rotation, flags и mask.
OBB сохраняет прежний выбор, gizmo перемещения и ручную правку. Capsule задаётся
радиусом и половиной длины центрального сегмента вдоль локальной Y; вращение
ориентирует эту ось. Несколько primitives образуют Compound. Кнопка NONE очищает
физическую коллизию, сохраняя модель. Изменения можно отменять.

Экспорт в выбранную папку создаёт подкаталог UID:

- JSON: `model.json`, PNG, `meta.json`, `collision.json`;
- OBJ: `model.obj`, `meta.json`, `collision.json`; при PNG также `texture.png`
  и `model.mtl`, с локальной ссылкой на текстуру.

OBJ экспортируется в уже преобразованных локальных координатах — transform
повторно применять не нужно. В папке не должно быть модели другого формата с
тем же UID. JSON сохраняет неизвестные исходные поля, parent flattening и свет.
`collision.json` теперь предназначен отдельному offline packer; старый consumer
OBB v2 потребует адаптации к новому контракту. Runtime packer, quantization,
BVH8, SIMD/AoSoA и Java binary format здесь не реализованы.

Архитектура: `model_import.rs` импортирует OBJ в индексированную mesh;
существующий JSON importer оставлен в `main.rs` для сохранения совместимости.
Редактор преобразует оба источника в локальные координаты и редактирует
primitives. `collision_asset.rs` задаёт независимый контракт коллизий;
`write_package` сохраняет модель отдельно от этого контракта.
Подробнее: [контракт collision asset](docs/collision-format.md).

Для AI, адаптирующего мод: [пошаговый контракт миграции](docs/ai-mod-migration.md).
В нём описаны legacy adapter, instance transforms, uint32 masks, точные коллизии,
региональные immutable snapshots, этапы packer и критерии измерения производительности.

Аудит хранения: OBJ corner использует 8 байт вместо 12 (24 вместо 36 на
треугольник; вершины и UV по-прежнему общие). Контракт коллизий валидируется
отдельно от UI, включая переполнение вычисленных bounds. Экспорт collision JSON
потоковый, с заменой через временный файл; отдельная JSON byte-buffer копия не нужна.
