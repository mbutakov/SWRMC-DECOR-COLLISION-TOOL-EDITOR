# Аудит хранения и экспорта

Проверен редактор; код мода и его реальные сцены здесь не исследованы.
Вместо заявления об «идеальном игровом формате» зафиксированы проверяемые
изменения и границы текущей реализации.

## Что исправлено

- Контракт v1 и его валидация отделены от UI в `collision_asset.rs`.
  Преобразование editor primitives находится в `collision_editor.rs`.
- Валидация legacy/editor snapshots больше не создаёт дополнительный Vec
  всех primitives. Импорт legacy JSON переиспользует уже разобранное дерево.
- Проверяются не только входные числа, но и конечность derived bounds;
  неподходящий OBJ transform не оставляет частично изменённые коллизии.
- Quaternion нормализуется и получает однозначный знак при экспорте.
- Collision JSON пишется потоково через временный файл. Убрана полная копия
  сериализованных байтов; неуспешная запись не обнуляет предыдущий collision.json.
- OBJ UV index использует Option<NonZeroU32>: corner 8 вместо 12 байт,
  triangle indices 24 вместо 36 байт. Снижение на 33.3% относится только
  к индексам, не ко всей модели, тексту OBJ, процессу или FPS. При 1 млн
  треугольников разница payload индексов — 12 млн байт, без учёта Vec capacity.
- Пустой произвольный JSON больше не интерпретируется как legacy NONE;
  min/max импортируется с явным типом AABB.

## Почему intermediate schema оставлена JSON v1

В экспорт не попадают mesh, editor state и debug данные. Математически
вычислимые поля не дублируются: AABB не хранит identity quaternion, Capsule
не хранит bounding extents. Общая asset identity находится в заголовке.
Flags/mask сохранены явно, чтобы не скрывать правила за неявными defaults.

Имена полей и composition дают небольшой overhead, но полезны для проверки,
диагностики и воспроизводимой offline-компиляции. Их сокращение само по себе
не ускоряет игровую физику. Примитивы и их порядок не оптимизируются с потерей
геометрии на экспорте. Нужную упаковку, alignment и пространственные индексы
должен выбирать отдельный compiler/runtime по нагрузке.

## Что не следует считать решённым

- Весь пакет файлов не является атомарной транзакцией: защита добавлена для
  collision.json. Потребитель должен дождаться успешного экспорта всей папки.
- OBJ парсится из текстового буфера; preview остаётся CPU painter с обходом
  и сортировкой треугольников. Бatching и меньшие индексы не превращают его
  в GPU renderer. Большие меши требуют отдельных замеров и, возможно, culling/LOD.
- Повторный экспорт одного состояния повторяем, но эквивалентные rotations
  после Euler/quaternion преобразований не обязаны совпасть побитно.
- В моде ещё предстоят точная narrow phase, world integration, scalar baseline,
  quantization/BVH/AoSoA и измерение latency/allocations. Готового runtime pack
  или доказанного выигрыша BVH8 эта работа не даёт.

## Проверка

Один успешно выполненный целевой набор: 7 тестов (4 audit + 3 существующих
интеграционных OBJ/JSON), без полного прогона suite. Проверены уменьшенный
layout и UV roundtrip, uint32 bits, invalid quaternion/overflow, rollback
transform, сохранность предыдущего файла при ошибке сериализации, экспорт
папок JSON/OBJ, reimport и smoke-render. FPS и производительность Java
не измерялись. `git diff --check` — без ошибок.
