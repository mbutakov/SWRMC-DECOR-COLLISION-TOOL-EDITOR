# Задание для AI: миграция мода на Collision Asset v1

Работай в репозитории мода. Сначала прочитай этот документ и
`docs/collision-format.md` из редактора. Найди существующий загрузчик декора,
формат размещений, систему коллизий и lifecycle чанков. Сохрани рендер JSON/OBJ
и поддержку старых сохранений. Не считай редакторский intermediate JSON готовым
оптимизированным runtime world. Сам мод в рамках аудита редактора не исследован:
конкретные классы, события, версии Minecraft, loader и JDK нужно определить там.

## 1. Сначала зафиксируй реальный контракт интеграции

Найди и перечисли места загрузки `model.json`, `collision.json`, `meta.json`,
legacy min/max и OBB v2, изменения позиции/вращения/масштаба декора, сохранения
и сетевой синхронизации. Установи текущий anchor: позиция блока, центр блока,
нижний центр или произвольный pivot. Не добавляй смещение 0.5 по догадке.
Проверь направления осей/порядок quaternion на асимметричной модели.

Выясни, какие запросы нужны: entity movement/sweep, raycast выбора, projectile,
overlap, pathfinding. Один успешный raycast не означает работающую физику.
Определи, может ли текущий API мода представлять OBB и Capsule точно. Если он
принимает только осевые боксы, потребуется отдельная интеграция narrow phase
и разрешения движения; bounding AABB нельзя молча выдавать за точную форму.

## 2. Загрузчик и переходный период

- Определяй новый формат по `format == "collision_asset"`, затем проверяй
  `version == 1` и `units == "blocks"`. Не путай эту версию с legacy OBB v2
  или версией сохранений мира. Неизвестный формат/версия — явная ошибка.
- Валидируй обязательные поля, типы, конечность f32, размеры, quaternion и
  вычисленные bounds. Quaternion: `[x,y,z,w]`, допустимое отклонение
  `abs(lengthSquared-1) <= 0.001`, затем нормализация. Нулевой quaternion запрещён.
- `asset` должен совпадать с UID пакета. При объединении resource packs задай
  namespace для внешнего registry key и правило обработки коллизий UID.
  Нельзя молча перезаписать один asset другим. Не меняй строку `asset` в файле.
- Legacy v2 и min/max конвертируй на входе в ту же внутреннюю модель. Никакого
  второго runtime движка для старых файлов. Переход не должен переписывать мир.
- Явный NONE: нет physics primitives, visual и identity asset сохраняются.
  Отсутствующий/испорченный файл не равен NONE. Для ошибки опиши политику
  загрузки; не превращай стену в проход по умолчанию.
- Flags/mask — все 32 бита unsigned. Читай JSON integer в long, проверяй
  `0 <= value <= 0xffffffffL`, затем сохраняй биты в int. `4294967295` становится
  `-1` как signed int и остаётся полной маской. Не используй проверку `mask > 0`.
  Для unsigned преобразований существуют методы [Java Integer](https://docs.oracle.com/en/java/javase/21/docs/api/java.base/java/lang/Integer.html).
- Значение отдельных битов редактор не определяет. Составь единую таблицу
  layer/query/flags для сервера, клиента и packer. Например, правило
  `(primitiveMask & queryMask) != 0` допустимо только как явно принятый контракт.
  Не интерпретируй flags как вторую маску без соглашения.
- Ограничь размер файла, число primitives и ресурсы парсинга на входе мода.
  Лимиты выбирай по реальным asset, с понятной диагностикой.

Парси JSON один раз при загрузке/перезагрузке. Общий immutable asset registry
хранит primitives один раз на asset. Размещение содержит asset index, стабильный
instance ID и transform. Не клонируй список primitives для каждого размещения
без измеренной причины. После компиляции освободи временное дерево JSON.

## 3. Геометрия и transforms

`Pworld = anchor + Rinstance * (uniformScale * Plocal)`, scale конечный и > 0.
JSON из редактора уже переведён в блоки:
`((x-8)/16, y/16, (z-8)/16)`. Экспортированный OBJ уже содержит transform
импортёра. Не дели повторно на 16 и не применяй OBJ origin второй раз.

- AABB в asset-local имеет identity orientation; после поворота размещения
  может стать OBB. Нельзя просто переносить его min/max без поворота.
- OBB: `Qworld = Qinstance * Qprimitive`, half extents умножаются на scale,
  center проходит полную формулу выше. Порядок умножения проверь на осевых тестах.
- Capsule: center — середина сегмента; локальные endpoints `(0, ±half_segment, 0)`.
  После rotation и scale добавь radius с тем же scale. Полная высота
  `2*(half_segment+radius)`. При `half_segment=0` получается сфера.
- Compound — union primitives. Не замещай его одним solid bounding box в narrow
  phase: у стула должны остаться проходы между ножками.
- В первой реализации допускай только положительный uniform instance scale.
  Nonuniform scale в общем случае меняет форму Capsule, а комбинация с OBB
  может дать shear. Такие преобразования нужно отклонять или отдельно bake,
  не «исправлять» одним максимальным коэффициентом молча.

Для broad phase вычисляй bounds на загрузке/изменении transform:
OBB `eWorld = abs(Rworld) * e`; Capsule
`eWorld = abs(axisWorld) * half_segment + (radius,radius,radius)`.
Тогда min/max = center ± eWorld; bounds Compound — union bounds детей.
Это консервативные bounds для отбора кандидатов, затем проверяется точная форма.

Не храни большие абсолютные координаты мира в float. Используй регион/чанк
как origin и локальные float, либо существующую double систему мира.
При raycast в local frame возвращаемую дистанцию/normal переводи обратно
с учётом масштаба; нормализация local ray не должна менять world hit distance.

## 4. Сначала корректный runtime, затем измеряемая оптимизация

Первая версия: scalar implementation с плоскими массивами примитивных чисел,
кэшированными bounds, стабильными индексами вместо объектного графа на каждый
primitive. Оставь простой reference query для сравнения. Стек обхода и временные
буферы переиспользуются; у параллельных запросов независимый scratch.

Включи новый путь за переключателем. На одинаковых запросах сравнивай старый
и новый результат для поддерживаемых старых форм, а для новых форм — reference
реализацию. Не сравнивай Capsule только с её bounding box.

Измеряй на настоящих сценах: память asset и размещений отдельно, время загрузки,
p50/p95/p99 запроса, число broad-phase кандидатов/narrow-phase проверок,
аллокации после прогрева и длительность обновления чанка. Зафиксируй CPU/JDK,
размер сцены и query mix. Цель — отсутствие аллокаций в устойчивом query loop,
а не отсутствие любых аллокаций при загрузке.

Tiny compounds могут обходиться линейно. Сравни linear/BVH4/BVH8 на реальных
нагрузках. BVH8 и AoSoA не гарантируют выигрыш сами по себе. Выбирай ширину блока
и способ SIMD по целевому JDK/CPU, оставь scalar fallback. Нельзя требовать
неподдерживаемые incubator modules без решения по минимальному JDK мода.
Не переходи на off-heap только ради названия: direct buffers имеют собственную
стоимость выделения; Oracle рекомендует их при измеримом выигрыше
([ByteBuffer](https://docs.oracle.com/en/java/javase/21/docs/api/java.base/java/nio/ByteBuffer.html)).

## 5. Packer и immutable static world — отдельный этап

Asset packer знает локальную геометрию, но без размещений не может построить
готовый collision world. Раздели скомпилированный asset cache и сборку world/
регионов из instance transforms. Для редактируемого Minecraft-мира «immutable»
означает неизменяемый snapshot региона, который можно заменить.

Статические размещения индексируй по покрываемым bounds регионам, не только
по чанку центра. Обеспечь queries через границы, oversized objects и дедупликацию
результатов по instance/primitive ID. Динамические объекты — отдельный индекс.
При добавлении/удалении декора перестраивай затронутые регионы; публикуй готовый
snapshot атомарно, проверяй revision, не применяй устаревшую фоновую сборку.

Для quantized bounds используй округление наружу: min вниз, max вверх. Учти
ошибку декодирования float, нулевой диапазон, out-of-range значения; не clamping
с потерей геометрии. Докажи, что декодированные bounds покрывают исходные, и
проверь отсутствие false negatives. Укажи допустимую пространственную ошибку
до выбора числа бит. Не квантизуй точные narrow-phase параметры автоматически
вместе с broad-phase bounds.

Будущий binary pack имеет собственные magic/version, endian, counts/offsets,
размеры секций, идентификаторы asset/instances, правила alignment, quantization
origin/step и проверку целостности/кэш-ключ. Проверяй переполнение `count*stride`,
диапазоны offsets, конечность значений и ссылки children/leaves до публикации.
Не сериализуй Rust memory layout и Java object layout. Порядок байт задаётся
явно: [ByteBuffer по умолчанию BIG_ENDIAN](https://docs.oracle.com/en/java/javase/21/docs/api/java.base/java/nio/ByteBuffer.html),
поэтому для little-endian pack выстави его перед созданием typed views.
Конкретный binary layout здесь намеренно не заморожен.

Cache key включает collision content, packer version и влияющие настройки;
world cache также включает placements/transforms/revision. Для повторяемых
сборок фиксируй порядок assets/instances, tie-breaks BVH и padding bytes.
Полная мировая BVH не должна перестраиваться каждый tick.

## 6. Минимальные критерии готовности AI-задачи

Выполни небольшой набор целевых проверок: legacy adapter; NONE; повернутый
асимметричный OBB и instance; Capsule/сфера; mixed Compound; полный uint32 mask;
пограничный чанк; reload/remove instance; malformed/unsupported input.
Для movement обязательно проверь sweep, тонкие препятствия и разрешение
контакта. Для quantization — покрытие исходных bounds и parity с reference.

Предоставь изменённые классы и точки интеграции, маленькие fixtures, результаты
проверок и замеров, совместимость сохранений и способ переключиться назад.
Различай измеренные результаты и предполагаемые улучшения. Не объявляй
поддержку Capsule/OBB законченной, если реализован только broad phase или raycast.
